Выполни задачу N из openspec/TASKS.md.

Порядок работы:

1. Прочитай файл RULES.md в папке openspec/ полностью. Правила обязательны, все запреты действуют без исключений.
2. Прочитай openspec/TASKS.md: правила использования файла, описание задачи N и «Готово, когда» её дня. Если задача помечена [Nikita], не выполняй её: сообщи, что она на авторе, и остановись.
3. Прочитай все спеки в openspec/specs/ (PRODUCT, DATA, FLOWS, MESSAGES, INFRA) и разделы, на которые ссылается задача. Учти и соседние разделы, которые связаны с задачей: поведение, данные и тексты должны совпадать со спеками.
4. Просмотри папку openspec/tasks/. Если для этой задачи уже есть файл, продолжай работу в нём, не создавай новый. Просмотри и файлы предыдущих задач, чтобы понять, что уже сделано, и не дублируй и не ломай готовый код.
5. Если что-то в спеках противоречиво, неполно или неоднозначно, или есть любой другой вопрос, не додумывай. Задай все вопросы мне разом до начала работы и жди ответа.
6. Создай или обнови файл задачи в openspec/tasks/ по правилам RULES: имя openspec/tasks/YYYY-MM-DD-<имя>.md (дату получи командой терминала, имя возьми из поля «Name» задачи), содержимое на русском: Описание, План, TODO, Действия. Архитектуру и структуру продумай заранее и запиши в плане.
7. Реализуй только задачу N, ничего сверх неё. Код чистый и читаемый, комментарии на английском и только там, где намерение неочевидно, тексты для пользователя только из MESSAGES.
8. Напиши тесты для новой логики и хендлеров, запусти весь набор тестов. Задача не завершена, пока тесты не проходят.
9. Обнови файл задачи: отмеченные пункты плана, TODO, список действий.

Жёсткие запреты (RULES):
- Не изменяй ни один файл в openspec/specs/, RULES.md и TASKS.md.
- Без моего отдельного разрешения не создавай и не меняй модели, таблицы, схему БД и миграции Alembic. Если задача этого требует, сначала спроси разрешение и жди.
- Не выполняй никаких записывающих операций git (add, commit, push, branch и т.д.). Чтение (status, diff, log) разрешено.
- Секреты, токены, ключи, ID, ссылки и любые значения окружения только в .env и .gitignore. Репозиторий публичный: ничего чувствительного не должно попасть в код, тесты, фикстуры, логи и документацию. Если добавляешь чувствительную механику, в этой же задаче добавь переменную в загрузку конфигурации, в .env.example (без значений) и проверь .gitignore.
- В логи нельзя писать Telegram ID пользователя; можно HID, текст распознанной речи, ID кружка.
- Новые зависимости можно добавлять по необходимости, обновляя файл зависимостей.

В конце дай короткий отчёт на русском: что сделано, какие файлы созданы или изменены, результат тестов, что осталось в TODO и что нужно от меня.
